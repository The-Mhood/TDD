G. Artist-ready production briefs

AUDIT RECOMMENDATIONS ONLY — briefs are not commissioned and authorize no source/design alteration

Use existing evidence first. Each brief starts only for the selected film shots and after its listed authority gates. Technical proposals remain labelled non-canon until separately accepted.

P2-B01 — Film shot-demand and authority handoff

Related gaps: P2-G00, P2-G01, P2-G02, P2-G21

Specialist: Story/editorial lead + layout supervisor + asset coordinator; CD approves the treatment

Start condition: Existing film evidence has been reconciled; no need to ask the owner to repeat a supplied decision.

Inputs

  • Complete scene/location registers and timeline
  • Sealed 193-source crosswalk and exact CD authority
  • Any existing film script/boards/animatic found during remaining inspection

Instructions

  1. Make one row per actually selected shot, not per game proposal: ID, beat, duration, temporal state, characters/wardrobes, visible and interacted props, set extent, camera envelope, effects and sound/graphics dependencies.
  2. Link every row to exact governing source IDs/hashes and permitted use. Mark proposed game activities/alternate endings as unselected unless expressly chosen.
  3. Identify required views/sections/contacts from those cameras; do not commission an encyclopedic sheet set. Flag contradictions and outside-authority needs rather than choosing a new design.

Deliverables

  • Versioned timed animatic/shot list if authorized by CD
  • Shot-to-logical-asset/version/authority matrix
  • Selected/excluded/proposed scope list and resource assumptions

Objective acceptance tests

  • Every selected shot has a CD-approved beat and no unsupported added people/animals/cultural action.
  • Every asset requirement joins exact design authority and a named technical deliverable; no orphan build or unallocated blocker.
  • Runtime, fps/aspect/colour/output and intended camera/acting requirements are explicit before estimates become commitments.

Do not: Do not turn 135 game entries, eight chapters, UI tiles, seven memories or three endings into a film build order. Do not reopen the closed 6/21/12 review or sealed193 decisions.

Dependencies: Remaining audit evidence; CD/editorial selection. This brief does not authorize artwork generation.

P2-B02 — Adanna: bounded technical character interpretation

Related gaps: P2-G03, P2-G05, P2-G07, P2-G08

Specialist: Senior character modeller with costume/groom technical artist; facial/body rigger joins before final topology

Start condition: CD has approved the exact separate production interpretation and resolved newly visible construction needed by selected shots; no preserved raster needs alteration.

Inputs

  • Approved Adanna portrait 1k08XH8VjNJAnSoMNU4YvBPtBEUdYD20y
  • Preserved LEFT_SIDE/BACK V003 and selected front/three-quarter V005 internal-study references
  • Interim partial upper-body Costume V002 1OcNpG55dadGkIUUar7W0Vm5Lkb2QGLJR
  • Selected camera/action rows from P2-B01

Instructions

  1. Build only the approved body/wardrobe interpretation in a separate native working asset, preserving likeness and left-sided identifiers. Do not derive height or a neutral body from a printed head grid alone.
  2. Keep skin, garments, straps, rigid ornaments and groom separate with explicit layer order, attachment points and collision roles. Unknown hidden construction remains a decision, not an artist invention.
  3. Choose deformation topology/UV detail from required face/shoulder/hip/hand shots; static rigid props do not need a universal all-quad rule. Keep modelling units/transforms and pivot convention documented.
  4. Review a neutral-light turn and only the commissioned close-up/camera poses against the authority packet before final texturing. No new character design is accepted by a technical pass.

Deliverables

  • Approved technical interpretation sheet/decision references where actually needed
  • Versioned native model with separated named objects, units, UVs and dependency manifest
  • Neutral and approved-camera review renders with source-ID comparisons
  • Rigger handoff: required motion/contacts and unresolved exclusions

Objective acceptance tests

  • CD confirms the approved likeness and identifiers in the actual camera envelope.
  • Required garment/skin surfaces are defined and no accessory/cloth/groom intersection is visible in required poses.
  • Original V003 side/back hashes are unchanged, still PRESERVE/UNAPPROVED; no automatic V004, mirror, blade or full-body approval inferred from V005.

Do not: No redesign, automatic full turnaround, scar duplication, BACK armlet flip, baldric reversal or use of CQ-9 weapon dimensions. Do not clear RQ-10-1/U-11 through modelling.

Dependencies: P2-B01; explicit CD technical-design authority; CQ-9 before weapon contact. Production work is not started by this audit.

P2-B03 — CQ-9 weapon/sheath construction and contact test

Related gaps: P2-G04, P2-G23

Specialist: Prop/weapon designer and modeller, character rigger, action animator; appropriate research where a factual claim is proposed

Start condition: CD resolves blade-design authority first. CQ-9 cannot be replaced by a good-looking sheath or a percentage measurement.

Inputs

  • Review-required blade board 1V12Sq2BZdIqjsgkx5GRpzGxc3nS3Gbac
  • Standalone sheath 1gAun9ET_l0Ro8-oD2yIeKILp9jBx0rjJ as non-authoritative appearance reference only
  • Approved character interpretation and commissioned carry/draw/contact shots

Instructions

  1. After design selection, document units/datums, blade/grip/guard sections, sheath throat/cavity, hanger/baldric interface and approved material intent. Show only missing angles/sections needed to build and operate it.
  2. Place the approved grip in the approved hand, check fingers/thumb and wrist/forearm travel, and solve only the shot-required carry/draw/re-sheath path. Keep original sources untouched.
  3. Use contact/attachment constraints with clear parent switches; test cloth and body clearance before final prop materials or action animation.

Deliverables

  • Signed exact-version weapon authority and metric construction specification
  • Native separated blade/sheath/attachment model
  • Real-time contact/draw test and collision/attachment notes
  • Known exclusions and source traceability

Objective acceptance tests

  • Approved geometry fits sheath and hand without impossible intersections.
  • Every commissioned action completes without attachment pops, side swaps or costume penetration.
  • No ~60cm/~42cm provisional value, 65%/70% guide or withdrawn coordinate is represented as original authority.

Do not: Do not insert a blade into preserved Adanna views, invent weapon canon or execute the withdrawn retouch guides.

Dependencies: CQ-9 design decision, P2-B01/P2-B02 and any relevant research/period decisions.

P2-B04 — Approved Chapter8 settings: common camera-ready spatial interpretation

Related gaps: P2-G09, P2-G10, P2-G21

Specialist: Environment/layout supervisor with architectural modeller; CD retains design/canon authority

Start condition: CD has selected film use/canon and approved necessary metric/layout interpretation; no dimension is invented as existing canon.

Inputs

  • Approved Hall V004 1MHCd25z3x-cfBUf-eoCJvDLqwvYj9Ins
  • Mothers' Courtyard V007 1EMYjEMCzfqhwEAfpvN8uDNfAddgLpVue
  • Nneka interior V003 1kT8ucpt6HVWhWEM8xvLRxTyGGjrNIxgf and house V004 1JIoAiQ20goibDA-ujYr95iyihBTLKZWj
  • Sealed Quarter V003 13jAtOMkXBazG2jbcFWZeBLsI1mufWJqU
  • Selected shot cameras, character/prop contacts and exact Bible sections

Instructions

  1. Create one coherent greybox plan for only the used spatial components. Record approved measurements, elevations, entrances, interior/exterior joins and camera paths.
  2. Preserve approved post/tree/door/roof/cloth/prop landmarks. Reconcile nested courtyard views in one spatial model; an inset is not proof of portal placement or parent assignment.
  3. Generate only missing reverse/elevation/section information needed by selected cameras. Keep approved sheen/carving and non-metric V013 study unchanged; do not revive folded-stair or add figures.
  4. Test the actual shot lens envelope and actor/prop clearance before final structural detail and UV/material production.

Deliverables

  • Source-linked plan/elevation/section set limited to shot needs
  • Native proxy scene with approved units/datums and cameras
  • Camera/actor traversal proof and inside/outside continuity sheet
  • Explicit unresolved/excluded areas; versioned layout authority

Objective acceptance tests

  • All selected cameras, doors and actor paths fit one approved layout without collisions or changing landmarks.
  • Inside/outside and reverse cuts agree; no required visible structure is hidden behind an unexplained illustration gap.
  • All five original boards are unchanged with design approval preserved; no canon, metric or production approval is silently inherited.

Do not: No automatic V013 resizing/sharpening, universal camera lock, remodelling approved art as a correction, or construction of an entire game world.

Dependencies: P2-B01/P2-G02; Chapter8 use/scale decisions, specialist structural interpretation only where selected shots demand it.

P2-B05 — Hero and background props: construction, reuse and operation

Related gaps: P2-G07, P2-G14, P2-G20, P2-G23

Specialist: Prop technical artist/modeller; relevant craft specialist for fishing, forging, weaving or instrument operation

Start condition: Each prop's design/form authority and required action are explicit; external gates are closed or the prop/action is excluded.

Inputs

  • Selected shot interaction list
  • Exact approved setting/character source IDs
  • Existing Research/CD restrictions for blade, loom, drums, paddles, medicine, regalia and cultural claims

Instructions

  1. Classify hero-contact, hero-visible static and background dressing. Set detail/UV/LOD budgets from actual screen size/parallax rather than one fixed polygon count.
  2. For contact props record units, grip/pivot/contact surfaces, attachment/hinge limits and required before/after state. For a functional mechanism obtain attributed construction evidence before modelling moving parts.
  3. Share approved repeated families/variants without copying unapproved motifs or changing character prop identity. Preserve clay E48 toy requirement, cold racks/hearths and tally-stroke-not-writing rules.
  4. SCN028 loom work cannot begin from an image labelled Akwete; SCN030 cannot be patched or regenerated. Paddle insertion waits for an approved reference; no heating cold racks to prove purpose.

Deliverables

  • Per-selected-prop authority/interaction sheet
  • Native model/material package with named pivots/attachments and approved variants
  • Shot-distance silhouette/detail proof and contact/operation test
  • Dependency/rights/research notes

Objective acceptance tests

  • Required contacts and mechanisms operate plausibly with no slipping/intersections or unauthorized shape/material/side changes.
  • Background detail survives the actual lens/motion without unnecessary unseen modelling or rigging.
  • No cultural meaning, species, ritual use or period claim is invented from an appearance.

Do not: Do not turn every visible jar/hoe/canoe into a separate hero build or use generic libraries to override source identity.

Dependencies: P2-B01/B03 as applicable; precise design decisions and Research/craft gates.

P2-B06 — Character rig, facial/groom and secondary-motion validation

Related gaps: P2-G05, P2-G06, P2-G08, P2-G24

Specialist: Character TD/body-facial rigger and animation supervisor; groom/cloth specialist only for demonstrated shot needs

Start condition: Visible design and topology/UV interfaces are approved; no rig is used to invent hidden character features.

Inputs

  • Released character/wardrobe/prop model packages
  • Approved selected expression/dialogue/action list
  • Okwu void, Idemili contact, Amadioha scar/lightning and Hollow King cavity constraints

Instructions

  1. Build required body/hand/eye/facial controls with stable asymmetry and explicit naming. Add phoneme/viseme capability only for actual approved language/dialogue; expression stills are targets, not a rig definition.
  2. Test the commissioned shoulder/hip/hand/neck range and contact tasks at actual shot distance; maintain eyelid/lip volume, scar placement and ornament attachment.
  3. Use a proxy groom/cloth collision setup before render density; choose constrained/animated secondary motion when sufficient. Cache expensive simulation only after blocking/animation inputs stabilize.
  4. Do not reveal or rig a prohibited Okwu face, infer python chirality from viewer-side reversal, or make a cavity pass through the body without authority.

Deliverables

  • Versioned native rig and deformation test scene
  • Approved-camera expression/action reel
  • Groom/cloth proxy and cache/dependency manifest where needed
  • Performance/memory report and animator-facing control notes

Objective acceptance tests

  • No required pose collapses skin, eyelids/lips or silhouette; no accessory/groom/cloth penetration in the approved envelope.
  • Contact and attachment switches are stable; secondary motion and caches replay deterministically through shot handles.
  • Animator can open/use the rig within measured machine capacity; original design restrictions remain intact.

Do not: No automatic full facial library, muscle system, cloth sim or creature rig solely because software supports it.

Dependencies: P2-B01/B02/B03/B05; approved facial/action scope and exact specialist character decisions.

P2-B07 — Chapter4 silver-overcast lighting: native proof, not another 2D replacement

Related gaps: P2-G15, P2-G22, P2-G25

Specialist: Lighting/look-development supervisor, with compositor for review transforms

Start condition: Native scene availability and its design authority are verified. This audit neither assumes a scene exists nor authorizes generating a replacement.

Inputs

  • Canoe Shed V002 16E4umob2MQdXGMRt1M9upT5yYOJ8-3UV
  • Two-House Landing V002 1Zjbufzzg6J4eL-OEKVZgBgNV8hMw1lig
  • Failed E53/E54 attempts as failure evidence only
  • Approved geometry/native shot scene, if existing, otherwise separately commissioned through prior gates

Instructions

  1. Retain approved canoe/house/rack/tool counts and geometry; use nondestructive sky/area-light/exposure/material controls to match the chosen soft silver-overcast chapter baseline.
  2. Render at the actual approved camera and a diagnostic angle only if authorized, with neutral and chapter review transforms recorded. Check shadow direction/softness, highlight colour and sky-to-ground ratio in motion.
  3. Keep the freestanding side-set fish rack cold/unlit. No fire, smoke, furnace, added people, sunny chapter variant or full-frame generative restaging.

Deliverables

  • Versioned native lighting setup and colour-management settings
  • Before/native-proof review frames and short moving proof
  • Performance/AOV/comp handoff and explicit approved geometry manifest

Objective acceptance tests

  • Warm directional sun/shadows no longer contradict silver-overcast direction in the commissioned shot.
  • Geometry/counts/staging remain the chosen approved design and the cold rack remains cold.
  • E53/E54 V003 failed relights are not named replacements; actual native proof is separately reviewed and approved.

Do not: Do not call a colour grade a physical relight or invent albedo/light reconstruction from a flattened JPEG.

Dependencies: P2-B01/B04/B05 where relevant; native scene and material release, no generation authorized here.

P2-B08 — Restricted fictional-design boundary: H3, masks and proposed practices

Related gaps: P2-G17, P2-G18, P2-G20

Specialist: Research lead, appropriately scoped cultural consultant and relevant living custodian if restricted practice is implicated; CD selects fiction

Start condition: The intended fictional use is stated precisely; historical/trashed reviews are not counted as live clearance.

Inputs

  • Exact H3 V002/V003 source IDs and separate Field of Cloth reference
  • Current D9/RQ-01 and SCN028/SCN030 controls
  • Selected film usage/copy/camera context; existing research evidence, including its restrictions and history

Instructions

  1. Separate visible image facts, proposed fictional interpretation and any asserted real-world practice/locality/meaning. Do not identify cargo as bodies or a mask as an authentic masquerade from appearance.
  2. Document who is qualified to speak to the exact proposed practice and what they can/cannot authorize. Obtain living-custodian direction only when the actual scope implicates it; do not invent universal restrictions or proxy scholarly authority.
  3. Give CD a source-cited allowed/excluded/needs-replacement boundary for the exact file/version/shot. No artist starts a visual repair as a workaround for an authority gate.

Deliverables

  • Attributed evidence/scope statement with source IDs and consultation provenance
  • Exact allowed/prohibited fictional use and residual limits
  • CD adaptation/exclusion decision; separate design brief only if later authorized

Objective acceptance tests

  • D9/RQ-01 and other protected gates have explicit exact-scope closure evidence or the material is excluded from commissioned work.
  • Fictional CD choice is not represented as authenticity, permission for an unrelated practice or restoration of a trashed review.
  • Field SUB005 and Landing SUB004 remain correctly mapped; SCN030 has no patch/regeneration order.

Do not: No invented consultant, custodian, clearance, ritual exception, recovered-original provenance or new generation.

Dependencies: P2-B01 selected use and existing authority controls. Consultation need is not waived by visual quality.

P2-B09 — Look-development, render and compositing proof package

Related gaps: P2-G06, P2-G22, P2-G25, P2-G26, P2-G29

Specialist: Look-development/lighting TD, compositor, editor/QC; CD approves look and storytelling

Start condition: Project colour workflow and native application/render versions are pinned; no source palette is mistaken for calibrated material data.

Inputs

  • Released geometry/rig/layout and exact chapter rules
  • Actual delivery/frame-rate/aspect/display targets
  • Approved moving shot samples covering skin/groom, dim interior, water/volume and emission where actually used
  • If selected: batch20 exact CH6threshold/Still WaterV002/Memory Room/Unfinished Edge sources and their approved impossible-space effect/camera interpretation

Instructions

  1. Document colour/data texture spaces, working scene-linear space, view transform and review/output encoding. Choose only needed shader channels, UDIMs and render AOVs, with tested tangent/displacement and depth/vector conventions.
  2. Render temporal tests at actual shot scale: close-up skin/eyes/hair, distant repeated thatch/foliage, dark voids and volumes, water/speculars and WHITE lightning only when selected. Preserve no-flame/no-wind and cold-rack restrictions.
  3. Deliver controllable graphics/holdouts/IDs/volumes and verify premultiplication/edge behaviour. Validate titles, diacritics and safe areas from approved copy; no game HUD is ordered automatically.
  4. Measure peak memory and p95 frame time; check denoising/flicker in motion rather than accepting a single attractive frame.
  5. For selected CH6impossible-space shots, prototype a separate reflected/portal scene or controlled camera/layer treatment with explicit occlusion/holdouts, mapping and exposure. Keep intentional midday/absent-door reflection distinct from physical dusk; do not relight the whole world or assume an expensive recursive/deep engine is required. Test recursive-room/world-edge beats only if commissioned.

Deliverables

  • Pinned native render/colour/comp templates and dependency manifest
  • Representative approved moving proof and reference comparisons
  • Documented image sequence/AOV/ID/holdout package as required
  • Reopen/re-render/recomp and QC/performance report

Objective acceptance tests

  • Reopened scene and comp reproduce the signed look without missing assets or colour shifts.
  • No visible seams, temporal flicker, unstable denoising, clipped unwanted light, bad alpha edges or prohibited design reveal.
  • Outputs match approved delivery; measured memory/time/storage fit actual capacity with agreed headroom.
  • Selected moving-camera/actor tests show no false-reflection/portal projection pops, incorrect parallax, alpha/occlusion leaks or unintended room/identity/lighting reveal; native mapping and comp reproduce the approved effect with original boards unchanged.

Do not: No fixed universal sample count, texture size, ACES adoption, camera lock or expensive renderer by default; prove what this film needs.

Dependencies: P2-B01 and released asset/animation inputs; P2-B10 capacity validation.

P2-B10 — Pipeline capacity, specialist staffing and purchase decision

Related gaps: P2-G01, P2-G27, P2-G28

Specialist: Producer + pipeline/render TD; CD sets standards, approves spend and delegates specialist execution

Start condition: Existing resource evidence is checked before requesting it again. No assumed hardware or film duration is used as fact.

Inputs

  • Actual CPU/RAM/GPU/VRAM/OS/drives/display/licences/network inventory
  • Team skills/availability, budget/schedule and approved delivery
  • Representative authorized proxy/native shot tests, not only this audit's sandbox

Instructions

  1. Run a small reproducible benchmark including the selected hero groom/cloth, repeated environment, darkest volume and water/emission case actually present. Record version/settings, median/p95 time, peak RAM/VRAM, cache IO and viewport response.
  2. Calculate total frames from approved durations/fps; render-hours from measured per-frame time and effective worker concurrency; storage from measured sequence/AOV/cache bytes and revision/backup policy. Include startup/retry/QC overhead explicitly.
  3. Choose essential DCC/paint/comp/edit/tracking/backup tools first. Add sculpting/texturing/simulation/farm capabilities only when the benchmark and assigned specialists justify their cost.
  4. Test an independent restore/reopen of a native asset and shot. Do not use downloaded sync/build scripts or change canonical Drive organisation to make the test pass.

Deliverables

  • Actual resource/licence/staffing worksheet and measured benchmark
  • Capacity/cost/schedule sheet with assumptions and headroom
  • Essential/conditional/unneeded software and hardware decision
  • Version-pinned handoff/backup/restore procedure with named owners

Objective acceptance tests

  • The approved quality target fits measured capacity or an explicit funded alternative plan; no quality downgrade is hidden as a beginner accommodation.
  • All specialist deliverables have an accountable executor; the CD is not assumed to perform every discipline.
  • Restore/reopen/re-render test succeeds independently; procurement/farm bookings are not made without owner approval.

Do not: No blind GPU/workstation purchase, fixed universal VRAM minimum, unsolicited paid stack or claim that a cloud farm fixes unresolved design.

Dependencies: P2-B01 selected cut/delivery, actual resources and approved budget; no procurement executed by this audit.
