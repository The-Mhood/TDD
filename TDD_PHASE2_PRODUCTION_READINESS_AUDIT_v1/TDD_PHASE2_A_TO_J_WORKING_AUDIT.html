Phase 2 — Visual Asset & Art Bible Production-Readiness Audit

A–J working report · coverage-qualified · audit only

Status: Phase 2 is not complete. This is not an all-file inspection certificate or a global production-readiness verdict.

The known folders have been enumerated, substantial actual visual/text inspection has been performed, and this package supplies the requested A–J structure with source-linked findings, gaps, briefs and technical gates. Many actual files still have not been visually or semantically inspected. The remaining queue is explicit. A file catalogue, hash match, image decode, prepared readpack or recommendation does not satisfy that outstanding work.

Session date: 16 November 2026 UTC. Dates embedded in source filenames, documents and Drive metadata are retained as source evidence, not silently adopted as this audit's date or proof of chronology.
Scope: the canonical production Art Bible and the enumerated related visual/reference/review/history/archive evidence.
Authority: owner/CD decisions and exact limited tiers remain controlling. This report changes no design, source, approval, canon, filing destination or external gate. Phase2 remote writes: 0.

Executive position

The inspected material is a substantial visual-development and narrative-design foundation, not a beginner exercise. It includes approved identity anchors, approved environment designs, accepted limited visual outcomes, useful material/atmosphere studies and unusually explicit negative constraints. It deserves a cinematic production pipeline and competent specialist execution.

It is not yet defensible to call the whole corpus production-ready. There are two different reasons, which must not be conflated:

  1. Audit assurance is unfinished: uninspected files may contain relevant evidence. This report does not say the entire project lacks native models, rigs, maps, cameras or technical documents.
  2. Specific inspected sources do not themselves deliver technical readiness: a flattened portrait is not topology or a rig; an environment perspective is not a measured connected set; a blade board with provisional dimensions is not an approved grip/draw system. Those limitations remain true even when the illustration has visual approval.

Recommended immediate sequence: finish evidence coverage → reconcile the actual film shot order and exact authority → close only the design/cultural dependencies affecting those shots → approve a bounded technical interpretation → validate a representative asset/shot through the H gates → scale production from measured results. Do not commission the entire historical game backlog or buy a large tool stack first.

No accepted visual pass is reopened merely because a technical test remains. No rejected/exploratory source is promoted because it looks useful. The CD remains final creative decision-maker; modelling, facial rigging, simulation, lighting and pipeline work may be assigned to specialists without lowering the quality target.

A2. Required per-asset reading of the catalogue

For a source ID, join A1 → inspection_ledger_rows_1based → A4; use A2/A5 to trace identical members and copies. Keep approval on the specific physical/decision identity, even when an observation is shared through exact bytes. C_PER_RASTER_EVIDENCE_MATRIX.csv records stage-evidence limits; it does not manufacture a technical pass.

The useful distinction is:

  • Reliable visible information: silhouette, observed colours under the depicted light, visible identity markers, surface appearance, composition and explicit printed qualifications.
  • Reliable written requirements: only the applicable governing Bible/CD specification, with historical/draft/proposed status retained.
  • Unknown unless separately established: physical dimensions, hidden surfaces, actual material chemistry, topology/UVs, fastening/attachment, rig/deformation, measured set connectivity, mechanics, animation, culture/period authenticity and production performance.

No universal resolution, texture size or sheet count is imposed. A large board with a small illustration panel or an upscaled source does not provide native close-up detail. A source may be sufficient for visual intent but insufficient as a moving-camera background or a construction specification. Required extra views come from actual shot coverage, not an automatic checklist of every possible sheet.

E2. Good early production candidates after separate authorization

The useful starting point is a representative chosen shot, not a world-sized build. Select it from the actual approved film treatment, considering the strongest applicable approved references and real production difficulty. A quiet domestic shot can still require excellent acting, skin, cloth, contact, lighting and cinematography; it is not a quality downgrade.

Once G01/G02 and applicable design gates close, independent work can safely include:

  • reference preparation and an approved camera/layout proxy for a selected setting;
  • material/look tests on approved forms while final topology/UV work proceeds, with interfaces controlled;

H2. Safe parallel work and change control

Parallel after H0: authority/reference indexing; editorial timing; resource/restore tests; approved material test surfaces; model/rig feasibility on controlled provisional interfaces. Parallel after H2/H3: texture work on stable UVs, rigging on approved topology, environment dressing on approved layout, lighting look tests on versioned assets. After blocking: final animation, then expensive collision-dependent caches; render and comp proof may run early, final frames use signed inputs.

Changes affecting silhouette, proportions, topology, UVs, contact dimensions, skeleton, camera/layout or wardrobe can invalidate downstream work. Raise a specific change record: exact asset/version, why, affected shots/stages, authority, migration/retest cost and approval. Never overwrite approved originals or silently update every linked scene to a new design.

H3. Proposed native package conventions

These apply to future working/published production deliveries, not renaming the existing Drive corpus:

  • Stable logical IDs plus variant/state and version; source filenames/IDs remain immutable provenance. Anatomical L/R is explicit; viewer-side labels are separate.
  • Explicit scene units, axis/up/forward, transforms, pivots and export scale; verify a neutral scale test through actual DCC handoff rather than adopting unapproved story dimensions.
  • Separate geometry, materials, textures, rig, groom, caches, cameras/lights and shot assembly; role/layer/collection names are consistent. Shared assets are referenced/version-pinned, not uncontrolled scene copies.
  • Model authority, material authority, rig version and permitted use are recorded independently. UV/UDIM, normals, displacement and colour conventions are documented only as needed by chosen tools.
  • Each publish carries application/plug-in versions, dependency manifest, source references/hashes, units, tests, restrictions and responsible sign-offs. Reopen on another working machine before handoff is called complete.
  • Keep source control for code/config/manifests; use appropriate large-file/versioned storage for native art and caches. Do not put large datasets/renders in ordinary Git or execute historical sync scripts to reorganize canonical Drive.

I4. Capacity and cost worksheet

Use the actual cut and benchmark—not invented duration or a still-image average:

  • frames = sum(ceil(approved_shot_duration_seconds × delivery_fps) + approved_handles).
  • render_worker_hours = frames × measured_p95_seconds_per_frame / 3600.
  • elapsed_render_hours ≈ render_worker_hours / effective_concurrent_workers, then add measured setup, failed-frame retry, cache/IO, comp and QC allowances. Hardware concurrency is not the same as usable throughput.
  • output_storage = measured_bytes_per_frame_with_required_layers × frames × retained_output_versions; add native assets, texture/groom/FX caches, editorial media and independent backups separately.
  • cost = actual labour + approved licences + tested local/remote compute + storage/transfer/backup + agreed contingency. Use real quotes only after scope and capacity are known.

Benchmark the representative selected cases: hero skin/eyes/braids/cloth; repeated thatch/foliage/earth; darkest readable interior/void; water/volume/emission where used; worst camera/rig/cache case. Record app/renderer/settings, peak RAM/VRAM, median/p95 frame time, IO, viewport/rig responsiveness, temporal artefacts and restore/reopen result. Agree headroom against the schedule rather than promising a universal safety percentage.
